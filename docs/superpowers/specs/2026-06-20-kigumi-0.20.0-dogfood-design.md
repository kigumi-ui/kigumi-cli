# Dogfood Runbook: kigumi@0.20.0 (published npm artifact)

**Date:** 2026-06-20
**Goal:** Exercise the published `kigumi@0.20.0` as a real user across React + Next.js, Free + Pro, and verify generated projects actually build. Produce a Pass/Fail findings report; file F-XXX backlog entries for real bugs.

## Artifact under test

`kigumi@0.20.0` installed from the public npm registry (`npm i -D kigumi@0.20.0`) into fresh projects — NOT the local build. Pro tier works because `WEBAWESOME_NPM_TOKEN` is set globally (`~/.npmrc`), so `kigumi` runs directly.

## Environment

- Ephemeral working dir: `$CLAUDE_JOB_DIR/tmp/dogfood/` (outside the repo; cleaned with the job).
- Run the CLI per-project via `npx --no-install kigumi` / `pnpm exec kigumi` (mirrors real install), never the repo `dist/`.

## Project matrix

| #   | Project                          | Scaffold                                    | Focus                                             |
| --- | -------------------------------- | ------------------------------------------- | ------------------------------------------------- |
| P1  | React + Vite                     | `pnpm create vite . --template react-ts`    | Full lifecycle, registry path                     |
| P2  | Next.js App Router (with `src/`) | `create-next-app --ts --src-dir --app`      | `'use client'`, `providers.tsx`, SSR hydration    |
| P3  | Next.js Pages Router             | `create-next-app --ts --no-src-dir` + pages | CSS policy (no global import), `_app` wiring hint |

## Command lifecycle (per project)

Run as a real user, capturing stdout + exit code for each:

1. `init` (framework auto-detect / explicit flag, `--yes`) → assert config + generated files (`lib/kigumi.ts`, styles, type decls).
2. `add` Free set: `button input card dialog` → assert wrappers exist, correct imports (`class` not `className`, framework-correct patterns).
3. `add` **Pro**: at least one Pro component → assert tier detection (Pro) succeeded and wrapper generated.
4. `list` / `status` → tier shown correctly (Pro), installed components listed.
5. `diff [component]` after a manual edit → assert snapshot diff detects the user modification.
6. `update` → three-way merge preserves the user edit, pulls template changes.
7. `upgrade` → bumps config `kigumiVersion`, no crash on the just-installed config.
8. `doctor` → diagnoses cleanly (no false positives on a fresh project).
9. `theme set` / `brand` / `palette` → theme files mutate as expected.
10. (P1 only) `registry` path: `registry init` / `registry validate` smoke.

## Acceptance criterion (the "ordentlich")

Each generated project MUST type-check / build:

- P1: `pnpm build` (vite) and/or `tsc --noEmit`.
- P2/P3: `pnpm build` (next build) or at least `tsc --noEmit`.

A project that generates files but fails to compile = FAIL, filed as a finding.

## Output

Findings report at `docs/superpowers/state/dogfood-0.20.0-YYYY-MM-DD.md`:

- Per-project, per-step Pass/Fail with evidence (command, exit code, key assertion).
- Real bugs → `F-XXX` rows in `backlog-bankruptcy-triage-decisions.csv` (per the new-findings convention), referenced from the report.
- A short Go/No-Go verdict on 0.20.0's real-world usability.

## Out of scope

Vue/Angular (chosen out), Next no-src variant (covered conceptually by P2/P3), reusable CI harness (separate follow-up if desired).
