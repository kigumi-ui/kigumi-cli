# Template typecheck shims

Ambient declarations consumed only by `templates/<framework>/tsconfig.json`.
**Not** shipped in the npm tarball (`package.json#files` whitelists `dist`,
`templates`, `llms.txt`, `README.md` only — this directory is excluded).

- `css.d.ts` — declares side-effect imports of `*.css` so React `.tsx` and Vue
  `<script setup>` blocks importing `./X.css` typecheck cleanly.
- `react-jsx.d.ts` — augments React's `JSX.IntrinsicElements` with the
  Web Awesome `wa-*` custom-element types from
  `@awesome.me/webawesome/dist/custom-elements-jsx.d.ts`. Mirrors the
  `wa.d.ts` shipped to user projects, but reads from the Free package
  instead of `webawesome-pro` (templates target both tiers).

When the user materializes a component, no shim is needed — Kigumi writes
its own JSX-augmentation file into the consuming project.

## Updating the Pro shim (maintainer workflow)

The Pro shim files (`wa-pro-paths.d.ts`, `wa-pro-jsx.d.ts`) are GENERATED by
`scripts/sync-wa-pro-shim.ts`. Do not hand-edit. Regenerate when:

- `@awesome.me/webawesome` (Free) is bumped in `package.json` — Pro follows
  Free's versioning, so a Free bump implies potential Pro changes.
- Pro adds a new component (extend the `PRO_COMPONENTS` list in the script).

### Workflow

```bash
# 1. Authenticate to the Pro registry. Token from .env → ~/.npmrc.
pnpm setup:npmrc

# 2. Temporarily modify root `.npmrc` to add the @awesome.me registry decl:
#    @awesome.me:registry=https://npm.cloudsmith.io/fortawesome/webawesome-pro/
#    //npm.cloudsmith.io/fortawesome/webawesome-pro/:_authToken=<token-from-.env>
#    //npm.cloudsmith.io/fortawesome/webawesome-pro/:always-auth=true
#    pnpm requires this in project-local .npmrc; ~/.npmrc is not consulted
#    for scoped registry auth. NEVER commit this modification — revert
#    immediately after install.

# 3. Install Pro locally; pnpm has no --no-save flag, so revert manifests after.
pnpm add -D @awesome.me/webawesome-pro
git checkout package.json pnpm-lock.yaml .npmrc

# 4. Regenerate the shim.
pnpm tsx scripts/sync-wa-pro-shim.ts

# 5. Review.
git diff typecheck-shims/

# 6. If method signatures drifted, regenerate React templates too.
pnpm tsx scripts/generate-react-templates.ts

# 7. Verify exit 0.
pnpm typecheck:templates

# 8. Commit shim + (if changed) regenerated templates.
git add typecheck-shims/ templates/react/
git commit -m "chore(typecheck): sync Pro shim for webawesome <new-version>"

# 9. Cleanup local Pro install.
pnpm remove @awesome.me/webawesome-pro
git checkout package.json pnpm-lock.yaml
```

### Why we don't ship Pro as a real dep

Pro requires a paid token (`WEBAWESOME_NPM_TOKEN`). Adding it to
`package.json` would force every contributor and CI runner to have the token
or fail `pnpm install`. Instead, the shim provides accurate Pro types
committed to the repo, generated on the maintainer's machine.

### When the shim drifts

If `pnpm typecheck:templates` fails with errors that look like Pro API
changes (missing methods, renamed props), re-run the sync workflow above.
The script reads Pro's actual `.d.ts` files as the source of truth.
