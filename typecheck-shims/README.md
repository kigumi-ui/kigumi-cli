# Template typecheck shims

Ambient declarations consumed only by `templates/<framework>/tsconfig.json`.
**Not** shipped in the npm tarball (`package.json#files` whitelists `dist`,
`templates`, `llms.txt`, `README.md` only — this directory is excluded).

- `css.d.ts` — declares side-effect imports of `*.css` so React `.tsx` and Vue
  `<script setup>` blocks importing `./X.css` typecheck cleanly.
- `react-jsx.d.ts` — augments React's `JSX.IntrinsicElements` with the
  Web Awesome `wa-*` custom-element types from
  `@awesome.me/webawesome/dist/custom-elements-jsx.d.ts`. Mirrors the
  `wa.d.ts` shipped to user projects, but reads from the Free package
  instead of `webawesome-pro` (templates target both tiers).

- `tsconfig.vue-pro.json`: not a shim, but the Vue Templates type-checked
  against the real Web Awesome Pro package (`pnpm typecheck:templates:pro`,
  CI `freshness` job), since `wa-pro-paths.d.ts` declares no properties and
  cannot vouch for a typed `elementRef` call (issue #136).

When the user materializes a component, no shim is needed — Kigumi writes
its own JSX-augmentation file into the consuming project.

## Updating the Pro shim (maintainer workflow)

The Pro shim files (`wa-pro-paths.d.ts`, `wa-pro-jsx.d.ts`) are GENERATED by
`scripts/sync-wa-pro-shim.ts` (`pnpm generate:pro-shim`). Do not hand-edit.
Regenerate on every Web Awesome bump, and when Pro adds a component (extend
the `PRO_COMPONENTS` list in the script).

`validate:generated-fresh` Check A regenerates both files and fails when the
committed ones differ, so a bump that skips this step cannot merge. The shim
had silently missed the 3.10 and 3.13 bumps before that gate existed.

### Workflow

The script reads the Web Awesome Pro package the docs site installs, found
through `resolveCem({ tier: 'pro' })`, so nothing is installed at the root.

```bash
# 1. Install docs dependencies, Pro included. docs/.npmrc reads the token
#    from WEBAWESOME_NPM_TOKEN (see `pnpm setup:npmrc`).
cd docs && pnpm install && cd ..

# 2. Regenerate metadata first: the shim's method signatures come from it.
pnpm generate:metadata
pnpm generate:pro-shim

# 3. Verify.
pnpm typecheck:templates
pnpm validate:generated-fresh
```

### What the Pro shim may contain

Web Awesome Pro is commercial software. Its license permits a seat holder to
use it but forbids handing Pro assets to people without a license, and this
repository is public. The generator therefore drops the documentation prose it
finds in Pro's type definitions and keeps only names, types and signatures,
which are the interface the templates must compile against. Do not re-add the
descriptions by hand: Pro licensees already see them in their editor, from the
package itself.

### Why we don't ship Pro as a real dep

Pro requires a paid token (`WEBAWESOME_NPM_TOKEN`). Adding it to
`package.json` would force every contributor and CI runner to have the token
or fail `pnpm install`. Instead, the shim provides accurate Pro types
committed to the repo, generated on the maintainer's machine.

### When the shim drifts

If `pnpm typecheck:templates` fails with errors that look like Pro API
changes (missing methods, renamed props), re-run the sync workflow above.
The script reads Pro's actual `.d.ts` files as the source of truth.
