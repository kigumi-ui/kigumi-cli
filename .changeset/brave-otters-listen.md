### Fixed

- `validate:cem-sync` no longer reports success for work it did not do. Its prop-value half compares every registry enum against the Custom Elements Manifest's attribute types, and it resolved that manifest through a probe that searched only `docs/node_modules` and only for the Pro package. When nothing was found it returned an empty map, the comparison read empty as nothing-to-compare, and the report printed "Prop-value drift: 0" above "CEM sync validation passed!". Two runs with and without the manifest on disk produced byte-identical output, both exit 0. The half exists because Web Awesome 3.6.0 widened a `size` enum unnoticed, and it had been silent on every CI run since. The two halves are now reported separately: component presence reads the committed component metadata and always runs, while prop-value drift states whether it was verified or not run, and only a run where both halves were verified prints an unqualified pass.
- The prop-value half now runs where a manifest actually exists. It sat in the token-free Quality Checks job, whose step comment claimed that installing docs dependencies there would add "no additional coverage"; that was false, because the half self-skipped in silence. It moved to the `freshness` job, which already installs the Pro package for Check A, so it costs no new install.
- `CEM components: 84` in the report came from the committed component metadata rather than from any manifest, so it printed 84 with no manifest on disk at all. It is now labelled `Metadata components`.
- `prebuild`'s metadata freshness check now says which of its four branches ran. It computed a reason and discarded it one line later, so "up to date with the manifest" and "no manifest on disk, nothing compared" were indistinguishable in a build log despite meaning opposite things. Exit codes are unchanged, so a build without docs dependencies still works.
- The second Custom Elements Manifest resolver is gone. `findCustomElementsJson`/`Sync` searched differently from `resolveCem`, and two search strategies is what produced the silently degraded skill-reference output in the previous release. All callers now share one resolver.
